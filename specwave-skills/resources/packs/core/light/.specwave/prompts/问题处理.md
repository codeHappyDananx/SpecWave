这张提示卡用于处理 Bug：先把问题复现清楚，再谈修复。

## 处理流程

### 1. 复现问题
- 最小步骤
- 期望 vs 实际
- 出现频率与影响面

### 2. 定位问题
- 可能入口
- 关键链路
- 可能根因与验证办法

### 3. 提出方案
- 修复方向
- 回归点清单
- 需要改代码时，先等用户明确允许

## 输出格式

### 收集信息

```
【阶段：问题处理】

我理解的问题：
- 期望行为：[用户期望看到什么]
- 实际行为：[实际发生了什么]
- 复现步骤：[如何复现]

---
这样理解对吗？
```

### 定位问题

```
【问题定位】

我看了 [文件列表]，发现：
- 问题原因：[一句话]
- 影响范围：[一句话]

---
确认定位正确？
```

### 修复方案

```
【修复方案】

建议修改：
- [文件]：[改什么]

回归点：
- [ ] [需要验证的点 1]
- [ ] [需要验证的点 2]

---
确认方案后，回复"开始"执行修复。
```

## 表达方式

- 先把现象与复现方式说清楚，再谈推测
- 把"我看到什么/我怎么验证/我不确定什么"区分开
- 术语不可避免时，顺手解释含义
