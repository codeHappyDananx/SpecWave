这张提示卡用于"把需求转化为技术设计"。核心原则：在需求确认后、任务拆解前，给出架构和组件设计。

## 设计文档结构

### 1. 概述
- 一句话说明设计目标
- 关键技术决策和理由

### 2. 架构（可选 Mermaid 图）
- 模块划分
- 数据流向
- 依赖关系

### 3. 组件与接口
- 组件职责
- 接口定义
- 边界约束

### 4. 数据模型
- 数据结构
- 状态管理
- 持久化方案（如有）

## 输出格式

```
【阶段：设计方案】

## 概述
[一句话设计目标]

## 架构
[架构说明，可用 Mermaid]

## 组件与接口
[组件职责、接口定义]

## 数据模型
[数据结构]

---
设计确认后，回复"继续"进入任务拆解阶段。
```

## 设计原则

- 遵循项目现有架构风格
- 参考 `project-map.md` 中的边界约束
- 新增组件要说明"它做什么 / 依赖谁 / 由谁依赖"
- 复杂设计可以分模块说明

## 禁止行为

- ❌ 不在设计阶段写具体代码
- ❌ 不跳过设计直接拆任务
- ❌ 不违反项目已有的架构约束

## 允许行为

- ✓ 给出多个方案时，说明推荐哪个及理由
- ✓ 引用现有代码说明复用点
- ✓ 标注需要用户确认的技术决策
