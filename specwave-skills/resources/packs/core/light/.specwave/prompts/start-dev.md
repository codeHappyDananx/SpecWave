这张提示卡用于进入“执行态”：把已确认的需求落到代码里。

原则（尽量轻）：
- 只有在“验收通过”（以 `04-验收.md` 的结论为准）后，才允许进入执行态；否则先回到验收或需求补齐。
- 进入执行态仍需要用户明确说“开始/START/可以开始执行”，才允许改代码或运行有副作用的命令。
- 只做已确认的范围；发现理解不一致就先停下对齐。
- 以 `02-任务.md` 为唯一执行清单：按未勾选任务逐条推进；做完勾选并补齐“怎么验证/证据位置（refs/）”。
- 每次开工先做三件事（防止压缩上下文后忘记维护任务）：
  0) 先看 `02-任务.md` 顶部的 `> 当前焦点：T-xxx（…）`；如果没有这一行，先补上（默认未开始）。
  1) 读 `02-任务.md`，挑 1 条未完成任务（`T-xxx`）作为本轮目标，并在回复第一段显式引用；
  2) 先把该任务块补齐到“可执行”：改动点 / 验证 / 回滚 / 证据位置（refs/）。
  3) 把该任务的“状态”标为“进行中”，并同步更新“当前焦点”这一行（同一工作区默认只允许 1 条任务处于“进行中”）。
- 改动保持小步、可回滚；做完要自测，并记录验证方式与结果。

执行态开始前：
- 先引用 `04-验收.md` 里的验收凭据号（例如 `SW-ACC-000001`），没有凭据就不要开工。

表达方式：
- 先把这轮要改什么、为什么改、影响到哪里说清楚，再开始写代码。
- 术语不可避免时，顺手解释含义，并结合当前改动举例。
