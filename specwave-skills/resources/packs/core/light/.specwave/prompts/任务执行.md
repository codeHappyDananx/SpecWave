这张提示卡用于"执行任务清单"。核心原则：只执行已确认的任务，每次只做一条。

## 进入条件

- 用户明确说"开始"、"开工"、"执行"等
- `03-任务.md` 已存在且有未完成任务

## 对齐当前任务

**优先级**：
1. 先找 `> 当前焦点：T-xxx（…）` 标记的任务
2. 找不到则找状态为"进行中"的任务
3. 都没有则选第一条未完成任务

**输出格式**：
```
【阶段：执行开发】
【当前任务：T-xxx】

任务：[任务描述]
改动点：[文件列表]
验证：[验证方式]

---
开始执行？
```

## 执行流程

### 1. 读取上下文
- 读取 `03-任务.md` 找到当前任务
- 读取 `01-需求.md` 了解需求背景
- 读取 `02-设计.md` 了解技术方案

### 2. 执行任务
- 按任务描述执行，不自行扩展范围
- 改动涉及职责/入口/边界时，同步更新 `project-map.md`
- 每完成一步，用一句话说明做了什么

### 3. 更新状态
- 执行完毕后勾选任务：`- [x] T-xxx`
- 补齐验证证据（截图/日志放 `refs/`）
- 更新当前焦点到下一条任务

## 执行中格式

```
【阶段：执行开发】
【执行：执行中】

> 当前焦点：T-001（进行中）

正在执行 T-001：[任务标题]
- [x] 改动点 1：已完成
- [ ] 改动点 2：进行中
```

## 发现问题时

如果执行过程中发现需求/设计有问题：

```
【暂停执行】

发现问题：[问题描述]
建议：回到 [需求/设计] 阶段修正

---
请确认是否回到需求阶段？
```

## 执行完成后

```
【执行完成】

已完成任务：
- [x] T-001：[任务描述]

验证证据：refs/[文件名]

---
继续下一条任务？或回复"验收"进入验收阶段。
```

## 禁止行为

- ❌ 不执行 `03-任务.md` 以外的任务
- ❌ 不自行扩展任务范围
- ❌ 发现问题时不能自行决定，必须暂停

## 允许行为

- ✓ 执行前说明计划
- ✓ 执行中实时更新任务状态
- ✓ 主动补充验证截图或日志
