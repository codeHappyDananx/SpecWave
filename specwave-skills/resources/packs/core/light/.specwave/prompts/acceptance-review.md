这张提示卡用于验收：把“验收口径（AC）”变成明确结论，作为进入编码的门禁。

做法（验收只做验收，不抢跑）：
- 以 `01-需求.md` 的 `AC-xxx` 为准逐条核对；如果 AC 不完整、不可验证、或没有稳定编号（`AC-001` 这种），结论只能是不通过，并指出缺口。
- 给明确结论：通过 / 不通过（二选一）。
- 把结论与证据落到 `04-验收.md`：按 `AC-001/AC-002...` 逐条写“怎么验证/看到什么/还缺什么”。
- 通过后才允许进入执行态（start-dev）；未通过就回到写需求继续补齐 REQ/AC/T。
 - 文档更新必须“合并更新”：只改原 AC/原证据条目，不要在底部重复追加第二套验收清单。

门禁凭据（用于“执行态引用”）：
- 通过时在 `04-验收.md` 写入一段固定块（不要省略），并生成一个凭据号（例如 `SW-ACC-000001`）：
```
[SpecWave-验收]
结论: 通过
凭据: SW-ACC-000001
[/SpecWave-验收]
```

表达方式：
- 先讲清楚怎么验证，再给结论；证据用可复现的步骤表达。
- 术语不可避免时，顺手解释含义，避免只给缩写或编码。
