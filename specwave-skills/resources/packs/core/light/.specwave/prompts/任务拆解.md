这张提示卡用于"把设计拆解为可执行任务"。核心原则：每条任务独立可执行，新窗口的 AI 能直接执行。

## 任务格式

每条任务必须包含：
1. **做什么**：任务标题行，含回链（关联需求：REQ-xxx, AC-xxx）
2. **改哪里**：具体的文件或模块
3. **怎么验证**：验证方式

示例：
```
- [ ] T-001：实现面板切换快捷键
  - 改动点：packages/ui-next/src/shell/Shell.tsx
  - 验证：按 Cmd+B 后面板收起/展开
  - 关联需求：REQ-001, AC-001, AC-002
```

## 独立可执行的关键

每条任务必须包含足够上下文，让新窗口的 AI 能直接执行：
- 明确的改动范围（哪些文件）
- 明确的验证方式（怎么确认做对了）
- 回链到需求和设计（为什么这样做）

新窗口的 AI 只需读 `03-任务.md` + `01-需求.md` + `02-设计.md` 就能执行。

## 输出格式

```
【阶段：任务拆解】

> 当前焦点：T-001（未开始）

- [ ] T-001：[做什么]
  - 改动点：[文件/模块]
  - 验证：[怎么验证]
  - 关联需求：REQ-001, AC-001

- [ ] T-002：[做什么]
  - 改动点：[文件/模块]
  - 验证：[怎么验证]
  - 关联需求：REQ-002, AC-002, AC-003

---
任务拆解完成。回复"开始"进入执行阶段（将切换到「开发执行者」角色）。
```

## 任务与需求回链

- 回链写在任务末尾，格式：`关联需求：REQ-xxx, AC-xxx`
- 一条任务可以对应多个 AC
- 确保所有 REQ/AC 都有任务覆盖
- 任务清单完成后，检查是否有遗漏的 REQ/AC

## 核心逻辑标注

涉及核心逻辑的任务，追加测试要点：

```
- [ ] T-003：实现状态持久化
  - 改动点：packages/ui-next/src/store/panelStore.ts
  - 验证：刷新页面后面板状态保持
  - 测试：验证 localStorage 读写正确性
  - 关联需求：REQ-003, AC-003
```

## 禁止行为

- ❌ 不让用户补充任务细节，直接给完整列表
- ❌ 不遗漏 REQ/AC 的回链
- ❌ 不把技术实现细节堆在任务里（那是执行阶段的事）
- ❌ 不写无法独立执行的任务
