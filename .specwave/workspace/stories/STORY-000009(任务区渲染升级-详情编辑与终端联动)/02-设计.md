# 设计方案

## 架构概述

任务区升级仍遵守 SpecWave 的三层解耦：

- `packages/contracts`：定义任务看板所需的 `ViewModel` 字段与 `UIIntent`（只放类型）。
- `apps/desktop/src/renderer/src/store.ts`：解析任务文件、维护任务 UI 状态、执行保存与终端联动等副作用（业务编排集中在 store）。
- `packages/ui-next`：只负责渲染任务卡片 + 详情抽屉，并派发 `dispatch(intent)`（不写业务逻辑、不直连终端/文件系统）。

## UI 目标效果（卡片化 + Tilted Card）

- 每个任务一张卡片，整体风格对齐 `shadcn/ui` 的按钮/抽屉/输入控件；卡片的“质感”由 Tilted Card（轻微 3D 倾斜 + 轻微缩放）提供。
- 列表信息“渐进披露”：列表只展示“状态 + 标题 + 摘要 + 快捷动作”，详情抽屉再展示完整任务块并支持编辑。
- “开始”按钮是卡片上的小悬浮快捷入口：点击后联动右侧终端，把开工模板写进终端输入区（不自动回车）。

## 数据模型（contracts）

### 1) 任务项来源信息（用于“只改这一条”）

现有 `TaskSourceVM` 只有 `statusPos`，只能支持勾选切换。为支持详情与编辑，需要把“任务块范围”带上：

- `statusPos`：`[ ]` 中间状态字符的位置（切换完成态用）。
- `blockStartPos/blockEndPos`：该任务块在全文的字符范围（替换块内容用）。
- `titleStartPos/titleEndPos`：标题在全文的字符范围（只改标题用）。
- `indent`/`level`：用于渲染缩进与判断块边界（解析用）。
- `stableKey`（可选）：从标题提取的稳定标识（如 `T-001`），用于保存后重新定位选中项。

> 块边界规则：从任务行开始，到“下一个任务行且缩进层级不大于当前任务”的前一行结束。

### 2) 任务项结构

- `title`：任务标题（原 `label`）。
- `summary`：摘要（默认取“做什么”第一句；解析不到则为空）。
- `checked` / `level`：保持现有语义。
- `source`：见上。

### 3) 看板 UI 状态

`TaskBoardVM` 承载任务 UI 的“可渲染状态”，避免 UI 自己推导业务：

- `items: TaskItemVM[]`
- `activeTaskId: string | null`：当前打开详情的任务
- `detail: { isOpen: boolean; mode: "view" | "edit"; draftTitle: string; draftBody: string }`

### 4) 新增 UIIntent

- `TASK_ITEM_OPEN`：打开详情（设置 activeTaskId + 初始化详情草稿）
- `TASK_DETAIL_CLOSE`：关闭详情
- `TASK_DETAIL_MODE_SET`：view/edit 切换
- `TASK_DETAIL_DRAFT_SET`：更新标题/正文草稿
- `TASK_DETAIL_SAVE`：保存该任务块（只回写这一个块）
- `TASK_ITEM_START`：点击“开始”（联动右侧终端并写入模板）

## 解析与回写策略（store）

### 1) 解析（parseTaskBoardV2）

输入：当前内容文本（`content.isDirty ? draftText : text`）

输出：`TaskBoardVM`

关键点：
- 以“按行扫描”为主，构建 `lineStartOffsets`，把“行号 → 字符位置”变成 O(1)。
- 识别任务行：`- [ ] xxx` / `- [x] xxx`（沿用现有正则口径）。
- 识别块边界：遇到下一个任务行时，用缩进层级判定归属；把上一个任务块的 `blockEndPos` 收束到边界前一行末尾。
- `stableKey`：从标题里提取 `T-001` 这类编号（提取不到则为空），用于保存后重选中。
- 解析 `summary`：在块内优先找 `- 做什么：` 的第一句，找不到就留空。

### 2) 勾选切换（沿用现有）

仍基于 `statusPos` 做字符替换并立即保存文件；保存成功后重新解析 `TaskBoardVM`。

### 3) 单条编辑保存（只改该块）

保存逻辑：

1. 从 `TaskItemVM.source.blockStartPos/blockEndPos` 切出原块文本；
2. 用 `draftTitle + draftBody` 组装新块文本（保留原缩进与 `- [ ]` 前缀口径）；
3. 生成 `nextText = text.slice(0, blockStartPos) + newBlock + text.slice(blockEndPos)`；
4. 调用 `saveTextFile(path, nextText, sha256)`；
5. 成功：更新 `content.text/draftText/sha256/saveStatus` 并重新解析任务看板；
6. 冲突：保持 UI 草稿不丢，提示“需要刷新后重试”。

> 组装规则：标题改动只影响任务行；正文改动只覆盖该任务块内的子 bullet 区域。

## “开始”终端联动策略（store）

目标：让用户“点一下就进入开工态”，但不替用户执行。

步骤：

1. 设置 `rightVisible=true` 且 `rightMode="terminal"`；
2. 若当前无终端面板：创建新面板并调用 `terminalCreateSession({ id, cwd })`；
3. 选中目标终端面板（`activePanelId` 指向它）；
4. 调用 `terminalWrite(id, template)` 把模板写进终端（不带换行）；
5. 若创建失败：把错误写入该终端输出区，并保持任务区可继续操作。

模板内容建议（示意，最终由 `03-任务.md` 拆任务时固化）：
- 第一行：`# 开始执行：<任务编号> <标题>`
- 后续：`pnpm ...` / `rg ...` / `specwave ...` 等“下一步命令草稿”

## 视觉、动效与可用性

### 1) Tilted Card 动效口径

参考：React Bits Tilted Card（`refs/AI-UI-设计参考.md` 已记录链接）

- 默认参数：小角度倾斜（`rotateAmplitude` 小）、小幅缩放（`scaleOnHover` 小），避免“晃”。
- 触发：仅 hover 触发；键盘 focus 不触发倾斜，只给清晰的 focus ring。
- 自动降级：
  - 用户开启“减少动态效果”时：禁用倾斜与缩放；
  - 任务数量过多（例如 > 80）时：降级为静态卡片，保证滚动与交互流畅。

### 2) 卡片布局与快捷操作

- 卡片主体可点击（打开详情），右侧悬浮“开始”按钮不抢主点击（独立按钮）。
- “开始”按钮使用 `Button variant="ghost" size="icon-sm"` + `Tooltip`。
- 勾选与开始互不干扰：勾选仍是独立入口，避免误触。

### 3) 详情抽屉（Sheet）

- 抽屉右侧打开，顶部显示任务标题与保存状态；
- 内容区可滚动，底部固定操作区（保存/取消/关闭）；
- 编辑态下：标题用 `Input`，正文用 `Textarea`；保存时显示“保存中/已保存/冲突/错误”。

## 关键技术决策

1. 详情容器选用 `Sheet`：项目已内置，且符合桌面端“侧栏详情”的 IDE 范式。
2. Tilted Card 仅做“质感层”：任务信息结构仍由 shadcn 的基础控件与项目 tokens 兜底，避免“只有动效没有信息层级”。
3. “开始”默认不执行：只写入终端、不回车，降低误操作风险；真正执行交给用户确认。
4. 解析与回写都在 store：UI 不做 markdown 处理，避免把业务逻辑写进组件。
