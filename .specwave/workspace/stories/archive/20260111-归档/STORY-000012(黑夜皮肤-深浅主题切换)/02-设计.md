# 设计方案

> Story：STORY-000012(黑夜皮肤-深浅主题切换)  
> 状态：已确认

## 架构概述

本 Story 的落地路径是“契约 → store → 根节点属性 → tokens 覆盖 → 清理硬编码颜色”：

1) `packages/contracts`：把 `ui.theme` 从字面量 `"light"` 升级为 `'light' | 'dark'`，并补一个新的 UIIntent 用于“循环切主色皮肤”。  
2) `apps/desktop` renderer store：  
   - 新增 `specwave_theme` 的读取与写入；  
   - `THEME_TOGGLE` 改为切换 `ui.theme`；  
   - 新增 `SKIN_CYCLE`（名称可调整）用于循环 `ui.skin`。  
3) `packages/ui-next`：根节点同时挂 `data-skin` 与 `data-theme`，并在 dark 时追加 `.dark` class，确保 shadcn 的 `dark:*` utilities 生效。  
4) `packages/ui-next/src/styles.css`：新增 `[data-theme="dark"]`，覆盖 `--sw-*` 与 shadcn tokens；白天模式保留现状。  
5) 把工作区中写死的浅色值（`#fff/#374151/#6B7280/#E5E7EB/...`）收口到 token，确保 dark 能全局生效。

## 组件职责

| 组件 | 职责 | 备注/边界 |
| --- | --- | --- |
| `packages/contracts/src/index.ts` | 唯一交互契约：补齐主题/皮肤切换的字段与 intent | 不放实现 |
| `apps/desktop/src/renderer/src/store.ts` | `dispatch(intent)` 的唯一实现：读写 localStorage、切换主题/主色 | 只在 store 编排，不把逻辑塞进 UI |
| `packages/ui-next/src/shell/SpecWaveApp.tsx` | 根元素应用 `data-skin`/`data-theme` 与 `.dark` | 仅负责“把 VM 变成 DOM 状态” |
| `packages/ui-next/src/styles.css` | tokens + reset：新增 dark 覆盖与语义 tokens | 白天 tokens 不改动数值 |
| `packages/ui-next/src/**/*.module.css` | 把硬编码浅色值收口成 token | WelcomePage 是特例，不纳入本 Story 影响面 |

## 数据模型

### ViewModel

- `AppViewModel.ui.theme: 'light' | 'dark'`
- `AppViewModel.ui.skin: 'blue' | 'purple' | 'green' | 'amber'`（现有）

### 持久化

- `localStorage.specwave_theme = 'light' | 'dark'`
- `localStorage.specwave_skin` 继续沿用现有口径（不改 key）

## 关键技术决策

1) **主题入口不加新按钮**：复用顶部栏现有“皮肤”按钮。点击切主题；Shift+点击循环切主色皮肤。  
2) **暗色落地靠 tokens，而不是满屏写 `dark:`**：  
   - 全局由 `[data-theme="dark"]` 覆盖 `--sw-*`（以及 shadcn tokens）；  
   - 组件样式只做“把硬编码颜色换成 token”，避免散落一堆暗色分支。  
3) **shadcn 的 dark 语义显式启用**：因为 `tailwind.config.cjs` 使用 `darkMode: ['class']`，dark 时根节点追加 `.dark`，避免跟随系统暗色导致忽明忽暗。  
4) **终端区域保持现状**：终端面板本身通过 `Panel[data-variant="terminal"]` 覆写了一套局部 token，本 Story 不改它的配色逻辑，保证终端观感不被全局主题牵连。
