# 需求文档

> Story：STORY-000006(提示词体系评审-闭环统一)
> 状态：编写中

## 概述

把 SpecWave 的提示词/roles/skills/CLI 调成：你不用懂术语，也能按提示一步步走完 spec；我说的每句话都能被你立刻验证（你说一句，我给一个明确结果）。

## 你最终会看到什么

- 你说“新建需求”，我第一行就是 `【spec 模式 - 诉求对齐】`，并且只问你 1 个最关键的确认点
- 我每次说“下一步”，都会用一句人话说明要干嘛（不只丢阶段名），并告诉你该回“继续”还是“开始”
- 工作区只出现三种主文档：`01-需求.md` / `02-设计.md` / `03-任务.md`；执行阶段只读 `03-任务.md`
- 你能用 `specwave create --plan` 反复校验：不会再出现“同一件事在不同文件里说法不一样”

## 需求清单

### REQ-001 进入 spec 的第一轮对话要“说人话”

- **你怎么触发**：你说“新建需求”（或“开 story/走流程”）
- **你会看到什么**：
  - 我先读 `.specwave/settings.json`、`.specwave/roles/需求分析师.md`、`AGENTS.md`
  - 我用 3~8 行说清楚：我准备做什么 / 我需要你确认哪一句 / 你下一步回什么
  - 这一轮只问 1 个问题

### REQ-002 提到阶段名时，不默认你懂

- **你怎么触发**：你问“下一步是什么”，或我主动推进阶段
- **你会看到什么**：我写“阶段名 + 一句话解释”，而不是只写“进入某阶段”

### REQ-003 4 阶段顺序固定，但提示要可操作

- **你怎么触发**：你在对话里连续回复“继续”
- **你会看到什么**：我只按这个顺序推进：诉求对齐 → 需求编写 → 设计方案 → 任务拆解（不跳阶段、不混阶段）

### REQ-004 文档命名统一（三文档）

- **你怎么触发**：我说“我已经把内容写到文档里了”
- **你会看到什么**：只会出现 `01-需求.md`/`02-设计.md`/`03-任务.md`，不再出现 `02-任务.md` 等旧命名

### REQ-005 不说抽象话当结论

- **你怎么触发**：任意阶段对话推进
- **你会看到什么**：我不会用“闭环/一致性/赋能/落地”这类词当结论；如果不得不出现，我会紧跟一句把它翻成人话

### REQ-006 执行门禁不抢跑

- **你怎么触发**：在“任务拆解”之前你就说“开始”
- **你会看到什么**：我明确说“还不能进入执行”，并告诉你缺哪一步（例如先把 `03-任务.md` 写出来）

## 验收口径

- **AC-001**：你说“新建需求”，我的第一行是 `【spec 模式 - 诉求对齐】`
- **AC-002**：你问“下一步是什么”，回复里包含“阶段名 + 一句话解释”，并给出可执行口令（继续/开始）
- **AC-003**：执行入口只读取 `03-任务.md`（`.specwave/prompts/开始执行.md`）
- **AC-004**：运行 `node specwave-skills/bin/specwave.js create --plan`，不会出现“阶段/文件名互相矛盾”的提示
- **AC-005**：`refs/评审报告.md` 至少列出 5 条问题，每条都写清：删掉哪句抽象话 / 换成哪句人话 / 怎么验证
