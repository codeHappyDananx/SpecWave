# 项目页签稳定与状态恢复（需求 + 验收）

## 这份文档怎么读

- 本文件先写“你最终会看到什么”和“怎么验收”，方便你快速判断是否符合预期。
- 最后一段是边界约束，给开发防跑偏用，看不看都行。

> 诉求一句话：新增项目页签不再“过一会儿自己消失”，关闭页签后能一键回到上一个项目，并且文件树/内容区/终端一起恢复。

## 你最终会看到什么

- 点顶部 “+” 新增并打开一个项目后：这个项目页签会稳定保留，除非你手动关闭或打开失败。
- 场景复现修复：先打开项目 A → 再 “+” 打开项目 B → 关闭 B：
  - 顶部自动切回项目 A 的页签；
  - 左栏文件树恢复为项目 A（不是空白、也不是项目 B 的残留）；
  - 中栏内容区恢复为项目 A 上次的内容（或按既有规则显示该项目的默认内容）；
  - 右栏终端恢复为项目 A（或按既有规则初始化终端区），不再出现“页签回来了但下面都没了”的断层。
- 你不需要再用“先切回 A，再关 B”这种绕路操作。

## 需求（我要什么）

### REQ-001 新增项目页签不再自动关闭

- 用户通过 “+” 成功打开项目后：该项目页签必须稳定存在，只有在用户明确关闭时才会消失。
- 若打开失败（例如用户取消、路径不可读等）：需要给出明确提示，并且不保留一个“半开状态”的页签。

### REQ-002 关闭当前页签后，自动切回上一个项目

- 关闭当前激活的项目页签时：应用必须自动激活一个“可继续工作的”项目页签。
- 默认切回规则（优先级从高到低）：
  1) 切回“上一次激活的项目”（最近一次历史）；
  2) 若无历史，切回相邻页签（优先右侧，其次左侧）；
  3) 若不存在任何项目页签，则显示应用的默认空态。

### REQ-003 切回项目时，三栏状态必须同步恢复

- 切回到某个项目页签时，下方三栏必须与该项目一致，不允许出现“顶部切回了、下方没切回”的断层：
  - 左栏：展示该项目目录的文件树与选中态（按既有规则懒加载也可以，但必须能正常操作，不得空白卡死）。
  - 中栏：展示该项目上一次的内容；若该项目没有历史内容，则按既有规则展示默认内容。
  - 右栏：展示该项目的终端区；若该项目没有终端会话，则按既有规则初始化终端区。
- 项目之间的状态必须隔离：A 的文件树/内容/终端不应被 B 覆盖或清空。

### REQ-004 UI 体验小优化（允许做，但不扩大范围）

- 顶部项目页签的激活态/hover/可关闭态更清晰，避免“看不出当前在哪个项目”。
- “+” 按钮与关闭按钮有明确提示（例如 tooltip），并且关闭后切回行为有轻量反馈（不打断操作）。
- 优先复用现有 UI 组件库（例如 `shadcn/ui`），避免自造样式和交互细节。

### REQ-005 边界与回归约束（给开发的硬约束）

- `packages/ui-next` 只渲染 `ViewModel`、只派发 `UIIntent`，不把业务状态写进 UI。
- 若新增/调整交互语义：先改 `packages/contracts`，再改 `apps/desktop` 的 store 实现，最后改 UI 消费。
- 三栏互不 import 的边界不被破坏。

## 验收（怎么判做完）

### AC-001 新增页签不自关

- 点 “+” 新增并成功打开一个项目后，等待一段时间（例如 5 分钟）页签仍保持存在，除非手动关闭。

### AC-002 关闭后能一键回到可用项目

- 打开项目 A → “+” 打开项目 B → 关闭 B：
  - 自动切回 A 的页签；
  - 左栏文件树/中栏内容区/右栏终端都能正常显示与操作，不出现空白或卡死。

### AC-003 不需要绕路操作

- 上述场景下，无需“先切回 A 再关 B”，直接关闭 B 也能回到 A 并继续工作。

### AC-004 UI 反馈达标

- 顶部页签的选中态明确；“+” 与关闭操作有清晰提示；关闭后自动切回的反馈轻量且不打断操作。
