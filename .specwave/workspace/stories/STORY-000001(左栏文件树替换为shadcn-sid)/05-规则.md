## 规则增量（仅记录新增/变更）

### R-1 shadcn Sidebar 的可追溯信息必须落盘

- 通过 shadcn MCP 引入 Sidebar 相关源码后，必须在本文件记录：
  - 上游来源链接（官方仓库/文档页面）
  - 采用的版本/commit（若可得）
  - 本仓库做过的“必要改动点”（只记结论，不写长过程）
- 本次落盘：
  - 上游：`@shadcn/sidebar`（`registry/new-york-v4/ui/sidebar.tsx`，new-york v4）
  - 本仓库落地：`packages/ui-next/src/primitives/shadcn/`（`sidebar.tsx`、`button.tsx`、`input.tsx`、`separator.tsx`、`sheet.tsx`、`tooltip.tsx`、`skeleton.tsx`、`use-mobile.ts`、`cn.ts`）
  - UI 使用点：`packages/ui-next/src/panels/left/LeftPanel.tsx`
  - 必要改动点：
    - import 路径从 `@/registry/...` 调整为本仓库相对路径（统一走 `primitives/shadcn`）。
    - 我们尝试过关闭 Tailwind 的 preflight 来减少全局影响，但会出现 `ul/li` 默认圆点/缩进等“系统样式漏出”。现在已开启 preflight，同时保留 `SidebarMenu`/`SidebarMenuSub` 里的 `list-none` + `p-0` 作为兜底，保证样式稳定。
    - 左栏用 `SidebarProvider` 包裹，并将 `Sidebar` 设为 `collapsible="none"`，避免与三栏布局的宽度控制互相打架。

### R-2 本 Story 会引入 Tailwind

- 引入 Tailwind 的目的很直接：复用 `shadcn/ui` Sidebar 的现成样式写法，减少手工改样式的成本。
- 引入 Tailwind 后仍要守住两件事：
  - 视觉口径不变：Flat/Light、禁阴影、反馈干脆（以 `SPECWAVESTYLE.MD` 为准）。
  - 样式边界清晰：不引入额外的全局“基础样式”去覆盖现有 reset/tokens；避免出现“改了侧栏，别的地方也跟着变”的连锁反应。
- 本次落盘：
  - Tailwind 配置：`tailwind.config.cjs`（Tailwind v4，已开启 preflight；补齐 shadcn 所需的 colors/token 映射）
  - PostCSS 配置：`apps/desktop/src/renderer/postcss.config.cjs`（使用 `@tailwindcss/postcss`，并把 `base` 指到仓库根，确保能扫到 `packages/ui-next`）
  - Tailwind 入口：`apps/desktop/src/renderer/src/tailwind.css`
    - `@import "tailwindcss/preflight.css";`（清掉浏览器默认样式，避免“系统控件感”）
    - `@config "../../../../../tailwind.config.cjs";`（明确用根配置，确保生成 `bg-sidebar` 等 class）
    - `@tailwind utilities;`（给 shadcn/ui 的 class 提供样式）
  - tokens/reset：`packages/ui-next/src/styles.css`（只放变量与 reset，不放 `@tailwind` 指令，避免 monorepo 下漏编译）
