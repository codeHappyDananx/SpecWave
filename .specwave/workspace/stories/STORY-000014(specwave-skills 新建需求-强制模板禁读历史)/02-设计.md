# 设计方案

> Story：STORY-000014(specwave-skills 新建需求-强制模板禁读历史)  
> 状态：已确认

## 架构概述

用“三重门禁 + 违规惩罚”把行为钉死：进入 spec 后先读模板再落盘；默认禁止读历史 Story；阶段只能单步推进，写完设计先等用户确认再拆任务。

## 组件职责

| 组件 | 职责 | 边界 |
|------|------|------|
| `specwave-skills/resources/packs/core/light/.specwave/prompts/新建需求.md` | 进入 spec 的第一道门：规定启动顺序、允许读取白名单、默认禁读历史 Story、违规惩罚动作、阶段单步推进口径 | 只负责“进入 spec 的启动逻辑”，不承载角色全流程细节 |
| `specwave-skills/resources/packs/core/light/.specwave/roles/需求分析师.md` | 第二道门：在需求/设计/任务各阶段重复强调“先读模板、禁读历史、逐步确认”，并把违规惩罚落成可执行动作 | 仍然禁止改代码；只规范流程与落盘 |
| `specwave-skills/resources/packs/core/light/project-root/AGENTS.md.template` | 第三道门：把关键门禁前置到项目根 `AGENTS.md`，降低模型漏读 role/prompts 时的失败概率 | 只放“必须遵守”的硬规则，不堆流程细节 |
| `specwave-skills/resources/packs/core/light/.specwave/templates/01-需求.md` | 需求文档模板真相源：提供固定结构与示例口径 | 模板本身不写业务内容 |
| `specwave-skills/resources/packs/core/light/.specwave/templates/02-设计.md` | 设计文档模板真相源：提供固定结构与示例口径 | 同上 |
| `specwave-skills/resources/packs/core/light/.specwave/templates/03-任务.md` | 任务文档模板真相源：提供固定结构与示例口径 | 同上 |

## 数据模型

```text
ReadPolicy（读取门禁）
- 会话来源：只以 .specwave/settings.json 的 currentSession 为准，不使用 legacy/globalCurrentSession
- 允许读取（最小集合）：
  - .specwave/settings.json
  - AGENTS.md
  - .specwave/roles/需求分析师.md
  - .specwave/workspace/project-map.md
  - .specwave/templates/01-需求.md
  - .specwave/templates/02-设计.md
  - .specwave/templates/03-任务.md
  - 当前 Story 目录：.specwave/workspace/stories/{currentSession.storyId}*/
- 禁止读取：
  - .specwave/workspace/stories/*（除当前 Story 以外的任何目录）

PhaseGate（阶段门禁）
- 每次只落盘一个阶段文档
- 阶段完成后只请求用户回复“继续”推进下一阶段
- 写完 02-设计.md 必须等待用户确认，才允许进入 03-任务.md

ViolationAction（违规惩罚）
- 触发条件：读取了非当前 Story 的 stories/* 文件，且用户未明确点名允许
- 处理动作（必须全部执行）：
  1) 立刻停止后续工作，不推进阶段
  2) 在当次回复里明确标记“违规：读了历史 Story”，并说明已停下
  3) 回到模板：重新按模板落盘当前阶段文档，再请求用户确认
```

## 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 门禁放哪里 | prompt + role + AGENTS 三处同时写 | 单点容易被模型漏读，多处重复能显著降低误读概率 |
| 历史 Story 策略 | 默认一律不读，只在用户点名 `STORY-xxxxxx` 时读 | 防止“找灵感”导致上下文污染与越界参考 |
| 阶段推进策略 | 单步确认：每次只做当前阶段，写完再等“继续” | 控制风险面，避免把多个阶段揉在一起误执行 |
| 惩罚形态 | 只在违规时触发，不增加正常路径 token 开销 | 惩罚要有效，但不能让正常流程变重 |
| 会话来源 | 只认 `currentSession`，忽略 legacy | 避免被旧会话残留误导去读历史 Story |

## 风险与依赖

- 风险：不同模型对“禁止读取”的自控强弱不一；用多处门禁 + 违规惩罚降低概率，但不能做到 100% 绝对。
- 依赖：项目必须存在 `.specwave/templates/`；若缺失，需先通过 `specwave create` 初始化补齐。
