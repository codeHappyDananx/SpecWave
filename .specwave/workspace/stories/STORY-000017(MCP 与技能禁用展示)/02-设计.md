# 设计方案

> Story：STORY-000017(MCP 与技能禁用展示)
> 状态：编写中

## 架构概述

用“左区常驻切换条 + 左区主体两种视图”的方式扩展现有左区；`MCP`：模型上下文协议服务 与 `skills`：技能 的数据与探测都由运行时（preload + 主进程）提供，UI 只渲染 `ViewModel`：视图模型 并派发 `UIIntent`：界面意图。

## 组件职责

| 组件 | 职责 | 边界 |
|------|------|------|
| `packages/contracts/src/index.ts` | 增加左区切换、能力视图的 `ViewModel` 与 `UIIntent` 定义 | 只放类型；不放实现 |
| `packages/ui-next/src/panels/left` | 渲染常驻切换条与能力视图；点击只 `dispatch(intent)` | 禁止读文件系统/运行外部命令 |
| `apps/desktop/src/renderer/src/store` | 接收 `UIIntent`，编排状态并生成 `AppViewModel` | 不直接做系统探测；通过 preload 能力调用 |
| `apps/desktop/src/preload` | 暴露“获取 `codex` 能力快照/探测”的桥接方法 | 只做桥接与参数校验，不承载业务编排 |
| `apps/desktop/src/main` | 执行 `codex`：工具名 `CLI`：命令行界面 调用、读取 `skills` 目录、执行 `MCP` 探测并做脱敏 | 不把结果写入磁盘；只返回快照 |

### 左区布局

- 左区内部拆两列：
  - 左：常驻竖向切换条（窄列，固定宽度）
  - 右：左区主体（工作区 / 能力视图 二选一）
- 切换条永远可见；只影响左区主体内容，不影响中区与右区布局。

### 切换条交互与样式

- 组件优先复用仓库内 primitives：
  - 外壳：沿用现有左区 `Panel`：面板结构
  - 切换：优先使用 `Tab`：页签（同项目现有样式），只做“工作区 / 能力”二态
  - 辅助操作（刷新/安装）：用 `IconButton`：图标按钮；悬停提示用 `Tooltip`：提示气泡
- 激活态：使用 `data-active` 或等效属性驱动背景色块（`Muted`）与文字色变化；不使用阴影。
- 动效：hover 允许轻微缩放（约 `1.02`）与颜色加深，时长约 `200ms`；不使用模糊与发光。

### 能力视图信息架构

- 顶部：标题“能力” + 一个“刷新”按钮（优先用 `IconButton`：图标按钮；或 `Button`：按钮 的 `secondary` 变体，避免 `outline` 自带阴影）。
- 内容区：`ScrollArea`：滚动区域，内部分两组：
  1) `MCP`：模型上下文协议服务
  2) `skills`：技能
- 每组标题行右侧提供“安装”入口：
  - `MCP`：提供“安装 MCP”，进入粘贴 `JSON` 并预览后确认
  - `skills`：提供“安装技能”，支持选择 `zip` 或 `md`（或包含 `SKILL.md` 的目录）
- 每一组用一个 `Card`：卡片 承载（`shadow-none`），组内用列表项展示：
  - 左：图标
  - 中：名称 + 简要说明
  - 右：状态 `Badge`：徽标（ok/失败/检测中/未知）
- 失败提示：单项失败在该项内展示一行简短原因；全局失败用 `Alert`：提示条（`destructive`）展示“无法探测”的总原因与建议。

### 视觉口径（Flat）

- 卡片：无阴影（`shadow-none`）；优先用背景色块分组（`bg-muted/10` 之类）而不是细线；需要边界时用更粗的边框（例如 `border-2`）。
- 字号：遵从现有左区口径（当前多处为 `text-[11px]` 到 `text-sm`）；以桌面信息密度优先。

### 安装弹窗（shadcn 组合）

现有 `shadcn/ui`：组件库 在仓库内已内置 `Dialog`：对话框、`Alert`：提示条、`ScrollArea`：滚动区域、`Badge`：徽标、`Button`：按钮、`Card`：卡片、`Textarea`：多行输入框，可直接组合实现安装流程。

Flat 约束落地方式：
- 不改全局组件默认样式，优先在使用处追加 `className="shadow-none"` 等覆盖（例如 `DialogContent` 默认带 `shadow-lg`）。
- `Card` 默认带阴影，使用处统一加 `shadow-none`，必要时用 `border-2` 强化结构，不用细线与阴影。

#### MCP 安装弹窗

- 入口：`MCP` 分组标题行的“安装 MCP”按钮
- 弹窗内容：
  - 顶部说明：此操作会调用 `codex mcp add`（官方）写入配置
  - `JSON` 输入区：多行输入（使用仓库现有 `Textarea`：多行输入框，并通过 `className` 覆盖去阴影）
  - 预览区：只展示脱敏后的预览（例如 `name`、`transportType`、`command`、`args`、`env` 键名）
  - 底部按钮：取消 / 安装（安装中置灰）
- 状态：安装中显示“检测中/安装中”，成功后自动关闭弹窗并触发一次刷新

#### skills 安装弹窗

- 入口：`skills` 分组标题行的“安装技能”按钮
- 弹窗内容：
  - 选择来源：按钮触发系统文件选择（`zip` 或 `md`；支持选择目录时，提供“选择目录”入口）
  - 预览区：展示将被安装的技能名称（来自 `SKILL.md` 元数据）与目标安装位置（用户级/项目级）
  - 底部按钮：取消 / 安装

## 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| `MCP` 配置来源 | 通过 `codex mcp list --json` / `codex mcp get --json` 获取 | 官方 `CLI`：命令行界面 能力；不依赖手工解析 `config.toml`：配置文件；避免版本差异 |
| `MCP` 连通性探测 | 通过官方 `MCP`：模型上下文协议 `SDK`：软件开发包 对服务做最小握手（`initialize`）并可选调用 `tools/list` | 不自写协议；复用官方实现；错误语义更可控 |
| `MCP` 安装方式 | 通过官方 `codex mcp add` 执行安装；来源为用户粘贴的普通 `JSON` | 安装走官方命令；`JSON` 只是输入载体，降低用户写 `TOML`：配置格式 成本 |
| `skills` 列表来源 | 按官方文档扫描 `$CWD/.codex/skills` 与 `~/.codex/skills` | 与 `codex`：工具名 的发现机制一致；不发明新位置 |
| `skills` 探测口径 | 以“结构完整性”作为可用性：是否存在 `SKILL.md`，以及前置元数据是否可解析 | 官方文档未提供运行态探测命令；避免执行任意脚本带来的安全与性能风险 |
| `skills` 安装方式 | 文件落盘到官方发现目录（用户级默认，必要时支持项目级） | 遵守官方发现机制；不要求用户改变使用方式 |
| 脱敏策略 | 永不展示 `env`：环境变量 明文值；仅展示键名（优先使用 `env_vars`，否则从 `env` 提取键名） | `codex mcp list/get --json` 会返回敏感值；必须防泄露 |
| UI 业务隔离 | 能力探测逻辑独立文件，UI 仅渲染与派发意图 | 遵守“UI 只渲染 `ViewModel`”门禁，降低耦合 |

## 交互契约包（涉及接口对接时必填）

本需求涉及“UI 控件 + preload + 主进程执行系统探测”，必须落盘契约。

- 契约文件：`refs/contracts/codex-capabilities.v1.md`
- 内容包含：请求/响应结构、状态机、失败语义、脱敏口径、回归清单

## 风险与依赖

- 依赖 `codex`：工具名 在用户系统可执行；若不可执行，`MCP`：模型上下文协议服务 只能展示为“未知/不可用”并提示安装/路径问题。
- `codex mcp list/get --json` 输出包含敏感字段；必须在主进程统一脱敏后再返回 UI。
- `MCP` 连通性探测可能拉起外部进程（`stdio`：标准输入输出 传输）；需要全局超时、并确保子进程可回收，避免残留。
- 安装会修改用户环境（写入 `codex` 配置、写入 `skills` 目录）；必须在 UI 明示影响范围，并提供失败可回滚策略（例如 `MCP` 安装失败时不保留半成品；`skills` 安装失败时清理目标目录）。
