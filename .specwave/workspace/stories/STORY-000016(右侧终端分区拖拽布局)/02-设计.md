# 设计方案

> Story：STORY-000016(右侧终端分区拖拽布局)
> 状态：编写中

## 架构概述

在右侧终端引入“终端分区停靠”的展示层：将“终端会话”与“分区区域（最多 4 个）”解耦，用 `ViewModel`：视图模型 驱动布局与拖拽投放，用 `UIIntent`：交互意图 描述移动/合并/交换/分割等操作，所有状态编排与约束收敛在 `store`：状态编排层。

## 组件职责

| 组件 | 职责 | 边界 |
|------|------|------|
| `packages/contracts/src/index.ts` | 定义右侧终端分区的 `AppViewModel.terminalDock` 与对应 `UIIntent`（拖拽投放、布局变更、分隔条拖动） | 只放类型与注释，不放实现 |
| `apps/desktop/src/renderer/src/store/handlers/terminalDock.ts`（拟新增） | 消费终端分区相关 `UIIntent`，维护分区布局状态与会话归属，保证“不留空区/最多 4 区/可合并可交换” | 只编排状态，不直接触达 UI |
| `packages/ui-next/src/panels/right/RightPanel.tsx` | 右栏壳：终端/对话切换、全局新增按钮；终端模式下渲染分区终端容器 | 不写业务逻辑，只派发意图 |
| `packages/ui-next/src/panels/right/TerminalDockView.tsx`（拟新增） | 渲染 1～4 区布局、区域标题栏（多会话标题）、拖拽命中与落点高亮、分隔条拖动 | 只消费 `ViewModel`，只派发 `UIIntent` |
| `packages/ui-next/src/panels/right/TerminalView.tsx` | 单个区域内渲染当前激活终端会话（复用现有 `xterm`：终端组件封装能力） | 不负责布局与拖拽；终端输入输出保持现状 |

## 数据模型

```ts
// 终端分区：最多 4 个区域；每个区域一个“当前激活会话”，其余会话作为标题栏可切换的会话标题
type TerminalDockVM = {
  // 全部终端会话（与现有 terminal panelId 概念一致）
  sessionIds: string[];

  // 右侧终端分区状态
  layout: {
    // single：1 区；splitV：左右；splitH：上下；
    // top1Bottom2：上 1 下 2；bottom1Top2：下 1 上 2；quad：四象限
    kind: 'single' | 'splitV' | 'splitH' | 'top1Bottom2' | 'bottom1Top2' | 'quad';

    // 当前显示的区域（顺序固定，和 kind 的位置映射绑定）
    regions: Array<{
      regionId: 'R1' | 'R2' | 'R3' | 'R4';
      tabIds: string[];        // 该区域包含的会话标题
      activeTabId: string;     // 该区域当前激活会话
    }>;

    // 分隔条尺寸（0~1），不同布局下含义不同；缺省用 0.5
    // split*：primary；top1Bottom2/bottom1Top2：primary + secondary；quad：row + col
    splitRatios: {
      primary?: number;
      secondary?: number;
      row?: number;
      col?: number;
    };
  };

  // 拖拽态（仅用于 UI 高亮展示，不落盘也可）
  drag?: {
    draggingTabId: string;
    fromRegionId: 'R1' | 'R2' | 'R3' | 'R4' | 'POOL';
  } | null;
};

// 拖拽投放：统一用一个意图描述“拖了什么、落到哪里、落点类型”
type TerminalDockDropIntent =
  | {
      type: 'TERMINAL_DOCK_DROP';
      tabId: string;
      from: { regionId: 'R1' | 'R2' | 'R3' | 'R4' | 'POOL' };
      to:
        | { kind: 'REGION_BODY'; regionId: 'R1' | 'R2' | 'R3' | 'R4'; edge: 'left' | 'right' | 'top' | 'bottom' | 'center' }
        | { kind: 'REGION_TAB'; regionId: 'R1' | 'R2' | 'R3' | 'R4'; targetTabId: string }
        | { kind: 'REGION_TABBAR_BLANK'; regionId: 'R1' | 'R2' | 'R3' | 'R4' };
    };
```

## 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 分区上限 | 固定最多 4 区 | 需求明确上限；可控的布局与回归范围 |
| “不留空区” | 区域 `regions[]` 永远要求 `tabIds.length >= 1` | 用户明确“不够就自动回退”，并且合并后也不保留空区域 |
| 2/3/4 自动切换 | 由 `TERMINAL_DOCK_DROP` 的 `edge` 与当前 `regions.length` 决定目标 `layout.kind` | 满足“拖到对应区域即自动切换布局”，无需额外按钮 |
| 标题栏落点语义 | `REGION_TAB`：交换；`REGION_TABBAR_BLANK`：合并；`REGION_BODY`：移动/分割 | 精确表达“拖到标题上交换、拖到标题空白合并、拖到区域内容分割/移动” |
| 分隔条拖动 | UI 派发 `TERMINAL_DOCK_SPLIT_RATIO_SET`（拟新增）更新 `splitRatios` | 分隔条是纯展示与交互采集；状态归 store 统一维护 |

## 交互契约包（涉及接口对接时必填）

本需求不涉及后端接口，但属于“前端控件 + 状态流转”，必须把 `UIIntent`：交互意图 与 `ViewModel`：视图模型 口径写进契约包，避免跨窗口实现靠猜。

建议落盘到 `refs/contracts/terminal-dock.md`（后续在「任务拆解」阶段创建），至少包含：
- `TerminalDockVM`：区域/标题/布局/分隔条比率的字段与语义
- `TERMINAL_DOCK_DROP`：三类落点（区域内容/标题/标题空白）与交换/合并/分割的行为矩阵
- `TERMINAL_DOCK_SPLIT_RATIO_SET`（拟新增）：分隔条拖动的比率字段含义与约束（最小/最大阈值）
- 回归清单：2→1 合并、2 区交换、1→2 分割、2→3、3→4、4→3/2/1 回退的最短步骤

## 风险与依赖

- `xterm`：终端组件 在多区域同时显示时，对尺寸变化更敏感；需要确保每个区域容器尺寸变化都能触发一次 `fit`：自适应并派发 `TERMINAL_RESIZE`：终端尺寸变更意图
- 拖拽命中在 Windows 下易受 `pointer`：指针事件 捕获与选择文本影响；需要明确区分“拖拽标题”和“选择标题文字”
- 多区域下的性能：最多 4 个 `xterm` 实例同时渲染，需确保输出写入仍走现有节流队列，避免卡顿
