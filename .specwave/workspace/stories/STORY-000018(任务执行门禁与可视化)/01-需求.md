# 需求文档

> Story：STORY-000018(任务执行门禁与可视化)
> 状态：编写中

## 概述

把“按任务推进”做成系统级门禁：任何执行类动作必须绑定到一条任务，并把任务状态切为 `[-]`（进行中）；中区同步以“转圈圈”渲染进行中；执行成功自动切为 `[x]`；失败/中断保持 `[-]` 并写原因，避免出现“已经做了但任务未更新”的严重断档。

## 你最终会看到什么

- 任务清单支持三态：`[ ]` 未开始、`[-]` 进行中、`[x]` 已完成。
- 中区打开任务清单/任务看板时，`[-]` 的任务会显示转圈圈，并高亮当前焦点任务。
- 触发执行时系统会先自动把目标任务置为 `[-]`；执行完成后自动置为 `[x]`。
- 执行失败/中断时任务保持 `[-]`，并在该任务下方追加一行脱敏原因，方便继续接着做。
- 通过 `specwave-router`：路由 或斜杠指令进入执行时，也会先检查并执行同样的任务门禁，不允许绕过。

## 需求清单

### REQ-001 任务三态语义

引入任务三态，作为“执行门禁”和“中区渲染”的唯一来源。

- **操作**：在 `03-任务.md` 的任务项中使用 `[ ] / [-] / [x]` 表示未开始 / 进行中 / 已完成
- **预期**：系统稳定识别三态；旧任务格式（仅 `[ ]/[x]`）仍可被兼容解析

### REQ-002 中区进行中渲染（转圈圈）

中区需要把 `[-]` 的任务渲染为“执行中”，让用户一眼看到当前做到了哪条。

- **操作**：在中区打开 `03-任务.md` 或任务看板
- **预期**：`[-]` 的任务前显示转圈圈；并高亮“当前焦点任务”

### REQ-003 执行门禁：任何执行都必须绑定任务

禁止“分析完就直接执行”绕过任务维度。

- **操作**：用户触发执行（例如点“开始”、或触发执行类意图/技能）
- **预期**：若未选定任务或任务未进入 `[-]`，系统阻止执行并提示原因；提供一键跳转到焦点任务/任务清单

### REQ-004 自动流转：开始置 `[-]`，成功置 `[x]`

执行过程中任务状态必须自动更新，减少人工遗漏。

- **操作**：开始执行某条任务
- **预期**：执行启动前自动把该任务写成 `[-]`；执行成功后自动写成 `[x]`；中区展示同步更新

### REQ-005 失败/中断留痕（保持 `[-]` 并写原因）

失败/中断必须可追踪，可复盘，可继续。

- **操作**：执行过程中失败或用户中断
- **预期**：任务保持为 `[-]`；在该任务下方追加一行原因（脱敏），例如缩进一行 `原因：xxx`

### REQ-006 `specwave-router` 门禁声明与校验

路由与斜杠指令必须明确“按任务推进”的门禁，并落实到执行前校验。

- **操作**：通过 `specwave-router`：路由 或斜杠指令进入执行
- **预期**：路由明确声明会检查任务门禁；真正执行前校验任务是否已进入 `[-]`，不满足则阻断并引导用户选任务

## 验收口径

- **AC-001**：在 `03-任务.md` 写 `- [-] T-001：...` → 中区显示转圈圈
- **AC-002**：未选任务时触发“开始/执行” → 被阻止，并提示先选择任务并进入进行中
- **AC-003**：开始执行某条任务 → 自动把该任务置为 `[-]`，中区同步转圈圈并高亮焦点任务
- **AC-004**：执行成功 → 自动把该任务置为 `[x]`，转圈圈消失
- **AC-005**：执行失败/中断 → 任务仍为 `[-]`，并追加一行脱敏原因
- **AC-006**：通过 `specwave-router`：路由 进入执行 → 同样受门禁约束，不能绕过

## 边界约束（可选）

- 同一时刻最多只允许一个 `[-]` 作为“当前执行中”（避免并行执行导致串线）。
- 只在任务清单语义下识别 `[-]`（避免误伤普通文本内容）。
