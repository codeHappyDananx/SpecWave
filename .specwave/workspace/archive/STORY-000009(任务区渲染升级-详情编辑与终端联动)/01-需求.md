# 需求

## 诉求

当前 `03-任务.md` 的任务模式渲染过于简单：只适合勾选，不适合推进任务。希望把任务区升级成更好用的“任务看板”，让每个任务能快速看全信息、能就地改，并且有一个小“开始”按钮能联动右侧终端进入开工状态。

## 你最终会看到什么

- 打开 `03-任务.md` 时，中区以卡片列表展示任务；层级、完成状态、标题一眼可读。
- 点某条任务会打开详情抽屉/弹层，展示该任务块的完整内容，并支持在详情里直接编辑与保存。
- 每条任务卡片右侧有一个小“开始”悬浮按钮；点击后会切到右侧终端，把该任务的开工模板写进终端输入区（默认不自动执行）。

## 范围与非目标

- 仅对“任务模式”生效（任务文件识别到 `03-任务.md` 等任务清单时）。
- 单条编辑只覆盖：修改任务标题、修改任务块详情文本。
- 不做：新增/删除任务、拖拽排序、跨任务批量编辑、点击“开始”后自动执行命令。

## UI 设计约束

- 任务区主要 UI 组件使用项目内 `shadcn/ui`（集中维护在 `packages/ui-next/src/primitives/shadcn`），保证一致性与质感。
- 任务卡片动效采用 React Bits 的 Tilted Card 风格（3D 轻微倾斜 + 轻微缩放），但整体偏“克制”，不做夸张旋转与大幅缩放。
- 交互与布局对齐 AI 工具常见模式：列表 + 详情抽屉、hover 快捷操作、清晰的 focus 状态与键盘可达。
- 设计方案需要给出参考来源与落地原则（将通过 Exa 检索并沉淀到本 Story 的 `refs/`，避免“凭感觉”改样式）。

### REQ-001 任务列表卡片化渲染

- **操作**：打开任务文件并切到任务模式。
- **预期**：以卡片列表展示所有任务行，包含清晰的层级缩进、完成状态与标题；在大量任务时滚动顺畅。

### REQ-002 任务详情查看

- **操作**：点击任意任务卡片（或其“详情”入口）。
- **预期**：打开详情抽屉/弹层，展示该任务对应的完整任务块内容（包含子 bullet）；支持关闭并回到原列表位置。

### REQ-003 单条编辑与保存（标题 + 详情）

- **操作**：在任务详情中进入编辑态，修改任务标题或任务块详情文本并保存。
- **预期**：只回写该任务对应的 markdown 块；保存成功后列表与详情同步刷新；保存失败会提示原因（含冲突提示与可恢复操作）。

### REQ-004 “开始”悬浮按钮与终端联动

- **操作**：在任务卡片上触发悬浮按钮，点击“开始”。
- **预期**：
  - 右侧自动切到终端视图并获得焦点；
  - 将该任务的开工模板写入终端输入区；
  - 默认不自动执行（不自动回车），由用户确认后手动执行。

### REQ-005 终端未就绪时的可用反馈

- **操作**：右侧尚无终端面板时点击“开始”。
- **预期**：自动新建终端面板并写入开工模板；若创建失败，给出明确提示且不影响继续浏览/编辑任务。

### REQ-006 任务区视觉与交互一致性（shadcn + AI UI pattern）

- **操作**：在任务模式下浏览列表、打开详情、编辑保存，并使用“开始”按钮联动终端。
- **预期**：组件观感与交互反馈统一（hover/focus/active 清晰可见），排版紧凑但不拥挤；Tilted Card 动效在大量任务下依然顺滑，并在“减少动态效果”偏好下自动降级；不出现浏览器默认控件样式“突兀混入”的情况。

## 验收口径

- **AC-001**：打开 `03-任务.md` 并切到任务模式 → 任务以卡片列表展示，能看出层级与完成状态。
- **AC-002**：点击任意任务卡片 → 能打开详情抽屉/弹层，看到该任务块的完整内容，关闭后回到列表。
- **AC-003**：在详情中编辑标题与详情文本并保存 → 文件内容更新且界面同步刷新；失败时有可理解的提示。
- **AC-004**：卡片上出现“开始”悬浮按钮，点击 → 右侧切到终端并聚焦，开工模板被写入终端输入区，且不自动执行。
- **AC-005**：无终端面板时点击“开始” → 自动创建终端面板并写入模板；创建失败能看到明确错误提示。
- **AC-006**：使用键盘 Tab 在任务区完成“切换焦点 → 打开详情 → 进入编辑 → 点击保存/关闭”等操作 → 焦点样式清晰可见，关键操作可达，整体视觉与 `shadcn/ui` 风格一致。
